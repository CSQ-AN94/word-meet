# 同词相遇

用户要在新文件夹里得到一个能联网的双人联想游戏，并使用 GitHub。

采用原生 HTML、CSS、JavaScript 和 PeerJS。GitHub Pages 托管静态网页，PeerServer Cloud 提供信令，词语通过 WebRTC 数据通道交换。无需用户提供数据库账号。相比需要配置数据库的方案，这条路径能直接从 GitHub 上线；公共信令和网络穿透仍然是外部可用性限制。

1. 两人通过八位房间码或邀请链接进入同一房间，最多两人。
2. 首轮各写任意词语，随后从上一轮两个词继续联想。
3. 用带随机盐、局号、轮号、席位的 SHA-256 承诺值锁定答案；双方提交后再交换原文并校验。
4. 首尾空格去除、Unicode NFC 规范化后严格相等即相遇；不忽略大小写、标点或词内空格。
5. 双方都点击继续才开始下一轮；成功后双方同意再来一局。
6. 展示对局足迹、连接状态、完整错误提示。重连开始新局；页面关闭后房间不会持久保存。
7. 手机和桌面均可使用；不做账户、排行榜、聊天、广告或无关功能。

实施顺序：先验证游戏协议，再实现房间连接与页面；运行 Node 协议测试及静态构建；使用 Codex in-app browser 验证可用的视觉和交互；初始化独立 Git 仓库，推送 GitHub 并部署 Pages。

重点验证：先提交不泄露词语、并发提交与重复消息、跨轮旧消息、篡改揭晓、双方准备、房间已满、离开与重连、部署子路径、窄屏布局。跨不同运营商网络的可用性不能由同机双标签测试证明。
